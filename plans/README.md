## Scope note

This was originally a targeted `plan <description>` run (user request: "Melhore o Hover dos buttons
pegue as cores"), which produced plan 001 (DONE) covering only button hover colors.

A full `improve-animations` audit (recon → audit all 8 categories → vet → plans) was then run
against the remaining unaudited surface — modals, kanban cards, the column-selector dropdown,
the row-action kebab menu, table row hover, and toasts — via 4 parallel category/area audits.
Plans 002–005 above are the top 4 findings by leverage (impact ÷ effort) selected from that pass,
written non-interactively (no user available to hand-pick findings mid-session) per the skill's
own guidance for that case.

### Findings not turned into plans (lower leverage or out of scope for a mechanical plan)

- **Kanban card move/reorder teleports** (HIGH, category 8) — `renderKanban()` rebuilds the whole
  board's `innerHTML` on every status change/reorder, so a moved card has no continuous DOM node
  to animate from/to. Fixing this properly needs a FLIP-style (or keep-node-and-tween-bounding-rect)
  rewrite of `cert_manager.kanban.js`'s render path, not a mechanical CSS/JS tweak — too large and
  architecture-changing for a plan meant to be executed blind by a low-context model. Worth a
  dedicated, hand-designed follow-up if the team wants to invest in it.
- **Kanban failed-drag rollback has no card-level visual cue** (HIGH, category 8) — the only
  failure signal today is the toast; the card silently snaps back via the same full-board rebuild
  as any other move. Depends on the same rendering rework as the item above.
- **Modal accessibility/easing findings** (MEDIUM: reduced-motion; folded into plan 004) and
  (LOW: hardcoded easing; folded into plan 002) — already covered, not separate plans.
- **Toast**: interruptibility is already correct (clean bill of health — CSS transitions, not
  keyframes, independent DOM node per toast, no shared-state bugs). Token consolidation folded
  into plan 002, reduced-motion folded into plan 004. Two LOW items were **not** turned into plans:
  the entrance scale of `0.98` sits just outside AUDIT.md's `0.9–0.97` target band (cosmetic, not
  worth a plan on its own), and there's no click-to-dismiss on individual toasts (a missed
  opportunity, not a defect — the transition-based exit path already used by the timeout auto-close
  would trivially support a click handler if the team wants it later).
- **Table row hover exists in AUDIT.md's "100+ times/day → no animation, ever" frequency bucket**
  (MEDIUM, category 1) — flagged as a tension worth a documented product decision (keep the
  120ms color-only feedback with a written justification, or remove it), not a mechanical fix a
  blind executor should make unilaterally. Pointer-gating for the same selector *was* folded into
  plan 004; the frequency question itself is left for a human call.
- **Kebab trigger has no open-state affordance** (LOW, category 8) unlike its column-selector
  sibling's chevron — a nice-to-have, not included to keep plan 005 focused on the higher-severity
  teleport fix.
